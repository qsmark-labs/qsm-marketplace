## Why

A read-only review of the whole qsm-langdev (2026-10-31, 24 findings, 22 verified against the code,
1 partly, 1 answered by the owner) found the system doing one job in several places and failing in
silence where the owner's rules ask for one path that fails loud: two judges for the commit and the
stop gate, limits outside the point table and processes with none, a 502-line import graph no
checker uses, a gates config whose errors read as "no languages", bandit at its defaults when its
config is missing, the first commit of a fresh repository blocked by the hook and passed by `check`,
and only a subagent's stop gated. The owner: "co by slo unifikovat, nebo foldnout dohromady, co by
slo zjednodusit, a kde by jsme mohli enforcnout lepsi code contracts / interfaces and types", all
24 to land "verified first", and the main agent's stop gated too.

## What Changes

- One judge: the commit gate and the stop gate classify verdicts through one function and one
  policy (a failed checker blocks; a missing binary or config blocks the commit and warns the
  stop).
- Every process a run starts (checker, probe, fixer, sentrux, gitleaks, detect-secrets, the rule
  pack fetch, the semgrep login probe) is bounded by its point's timeout from the `POINTS` table
  and its process group terminated; the private 15 s and 10 s limits go.
- The main agent's stop is gated with the same binary and cap as a subagent's (a classic `Stop`
  hook); the stop gate names untracked files beside unstaged changes.
- **BREAKING**: `.qsm-langdev/gates.json` that does not parse, is not an object, or names an unknown
  language or gate fails loud instead of reading as defaults.
- A checker with its own config file fails when that file is missing (bandit without
  `bandit.yaml`), never runs at its defaults.
- The first commit of a repository is reported, never blocked, by the hook as by `check`.
- **BREAKING**: the import graph and the `changed+N` file set go (no checker declares them).
- **BREAKING**: `install --lang` goes; hooks are shell only, and an existing non-shell hook is named
  with the line to add by hand.
- Types: a verdict, a score's failure, a tree side and a gate name become discriminated unions or
  branded types, so the wrong state does not compile; one point family; one git helper with one
  environment policy; dead fields and copies go.
- Docs: README, USAGE, INSTALL and help say what the code does (four points, targets, `slow:`,
  doctor's median, staged only, in-place edit); `doctor` no longer describes a tree-derived mode.
- One standard negative eval per language plugin, generated by the eval gate, replaces six copies.
- Before this lands, `langdev-point-targets` closes: 4.1 by asserting the existing `profileGaps` and
  `registryGaps` in tests, its docs and re-measure lines done, its CI lines (5.2 to 5.4) moved to a
  new change `langdev-ci-point` that waits for `SEMGREP_APP_TOKEN`, then archived, so the main spec
  stops describing a working-tree shipped side and an edit hook that compares against HEAD.

## Critiques

- Devil's advocate: one judge could change what the stop gate does today. Fixed: the policy is
  written in the spec as a table and the existing gate-hook and gate-runner tests must pass
  unchanged.
- Devil's advocate: failing on an unknown language in `gates.json` breaks a repository that names a
  language a later version drops. Waived: no history, no compatibility; the message names the
  field and the known languages.
- Future archaeologist: why is there no import graph when the spec once had one? Fixed: git holds
  it; the proposal says no checker declared `changed+N`.
- Scope sniper: findings 10 (one limiter) and 20 (git index only for structure) have unmeasured
  gains. Fixed: each is a measure-first line; it lands only when the measurement shows seconds.
- Scope sniper: finding 11 (one git helper) rests on an unverified consequence. Fixed: its line
  first proves the `git commit <paths>` case in a test; the helper lands either way, the env policy
  follows the proof.
